# seminar-orc-site

VK Orchestrator のセミナーで、issue を自動処理させるデモに使う静的 HTML のサイトです。

架空の会社「株式会社サンプルウェブ」の、1 ページ完結のビジネスサイトです。会社名・住所・電話番号などはすべてダミーです。

## ファイル構成

- `index.html` : ページ本体
- `css/style.css` : スタイル

## 表示の確認

ビルドは不要です。`index.html` をブラウザで直接開いて確認できます。

ローカルサーバーで確認する場合は、リポジトリのルートで次のコマンドを実行し、`http://localhost:8000/` を開きます。

```
python3 -m http.server 8000
```

## ハンズオン手順

このサイトに「ページトップへ戻るボタン」などの機能を追加する issue を立て、VK Orchestrator に処理させます。issue を雑に書いても、AI が画面の案をモック画像付きで提案してくるところまでを体験します。

### 事前に済ませておくこと

- VK Orchestrator をインストールし、初回セットアップ（`/vk-orchestrator-setup`）を終えている
- `gh auth login` で GitHub にログインしている
- 設定の `github.owner` に、自分の GitHub アカウント名が入っている
- 設定の `org.review_assets_repo` に、画像を置くリポジトリが登録されている

`org.review_assets_repo` が空だと、モック画像やテストのスクリーンショットが付かず、文字だけの報告になります。初回セットアップの対話で作成・登録できるので、「未設定のままにする」を選ばないでください。画像置き場のリポジトリは private で問題ありません。

### 1. テンプレートから自分のリポジトリを作る

1. このリポジトリのページ上部にある「Use this template」→「Create a new repository」を選ぶ
2. Owner に自分のアカウントを選び、リポジトリ名を付けて「Create repository」を押す

このリポジトリに直接 issue を立てたり、fork したりはしないでください。自分のリポジトリでないと、AI がブランチを push して PR を作れません。

### 2. 自分のリポジトリを clone する

VK Orchestrator の設定で作業フォルダとして登録しているフォルダ（`workspace.search_paths`）の中に clone します。`<自分のアカウント>` と `<リポジトリ名>` は自分の値に置き換えてください。

```
gh repo clone <自分のアカウント>/<リポジトリ名>
```

clone できたら、`index.html` をブラウザで開いて、今の画面を見ておきます。

### 3. 取り込み用のラベルを作る

VK Orchestrator は、`task-queue` ラベルの付いた issue を拾います。テンプレートから作ったリポジトリにはこのラベルが無いので、作っておきます。

```
gh label create task-queue -R <自分のアカウント>/<リポジトリ名>
```

### 4. issue を立てる

自分のリポジトリに issue を作ります。書き方は雑で大丈夫です。例を載せます。

```
ページトップへ戻るボタンを追加したい。
実装前に仕様を相談させてください。
```

「実装前に仕様を相談させてください」の1行を入れると、AI がいきなり実装に進まず、先に案を見せてくれます。

ほかの題材の例です。

- お知らせのバナーを出したい
- ダークモードの切り替えボタンを付けたい
- 記事の下に SNS のシェアボタンを付けたい
- スマホでメニューを開きやすくしたい

issue を作ったら、Assignees に自分を設定し、Labels に `task-queue` を付けます。

### 5. タスクを「実行待ち」にする

1. VK Terminals のサイドバーのタスクリストに、立てた issue が「承認待ち」で並ぶまで待つ（巡回のタイミング次第で、1分ほどかかります）
2. マージのしかたを「手動」にする
3. ステータスを「実行待ち」に変える

ペインが開いて、AI が作業を始めます。

### 6. 仕様の提案に答える

しばらくすると、issue に仕様の提案がコメントされ、タスクが「入力待ち」になります。コメントには、ボタンの位置や見た目の案が、モック画像付きで載っています。

コメントの最後にある回答用のテンプレートをコピーし、選びたい案を書いて issue に返信します。空欄の項目は推奨案で進みます。画像が付いていなければ、返信で「案を画像で見せて」と頼むこともできます。

### 7. PR を確認する

回答すると、AI が実装・レビュー・テストを進め、PR を作ります。PR には、実装後の画面のスクリーンショットが付いたテスト報告が投稿されます。

PR のブランチを手元に取り込み、`index.html` をブラウザで開いて動きを確かめます。問題がなければ PR をマージします。

### うまくいかないとき

- タスクリストに issue が出てこない: issue に `task-queue` ラベルと自分のアサインが付いているか、設定の `github.owner` に自分のアカウント名が入っているかを確認します。
- モック画像が付かない: 設定の `org.review_assets_repo` に画像置き場のリポジトリが登録されているかを確認します。
